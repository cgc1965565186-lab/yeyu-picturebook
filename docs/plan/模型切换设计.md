# 模型切换设计

> 需求：在使用时可以切换模型。
> 结论：**做，但只允许"向前生效"** —— 切换改变的是"接下来的调用用谁"，绝不改写"已经生成的东西是谁做的"。
> 这条限制不是保守，是唯一能让作品说得清来源的做法（V2.1 §6.5 的 release 一致性要求）。

---

## 1. 先拆"切什么模型"

"模型"在这个项目里其实有四个位置，能切的和不能切的完全不同：

| 位置 | 候选 | 在哪里切 | 影响范围 |
|---|---|---|---|
| **视频生成** | `MiniMax-H3-Lite` 480P / `MiniMax-H3` 768P / `MiniMax-H3` 2K | 制作台 | 下一批镜头，成本差 5 倍 |
| **问答推理** | `deepseek-flash`（主）/ 备用 | 阅读设置（家长可见） | 下一轮回答，延迟与质量 |
| **ASR** | 云端 `qwen-audio-3.1-asr-flash-streaming` / 本地 Qwen3-ASR | 设置（高级） | 下一句话的识别 |
| **TTS** | `speech-2.8-turbo` / `qwen-audio-3.1-tts-flash` / 本地旁白 | 设置（高级） | 下一段播报 |

**视频生成是重点**，因为它是唯一"花了钱、且结果不可逆"的切换。其余三个切错了只是下一轮效果差一点。

---

## 2. 一条铁律

> **切换只影响后续调用。已生成的资产永远保留它自己的 `provider / model / profile`，不因切换而改写。**

推论三条，都是硬规矩：

1. **一个成片只能有一个视频 profile。** 不允许"前 5 个镜头 Lite、后 5 个镜头 H3"拼成一条片——画质断层一眼可见，且无法用一句话说明它是什么规格。
2. **切换后必须新建 compilation**，旧 compilation 原样保留（它是历史，不是错误）。
3. **评测结果不可跨模型合并。** C6 的 100 道题如果一半用 Lite、一半用 H3，那不是"一次评测"，是两次。

---

## 3. 数据结构

```ts
type ModelBinding = {
  video:   { provider: "minimax" | "fixture"; model: "MiniMax-H3" | "MiniMax-H3-Lite"; resolution: "480P" | "768P" | "2K"; profile: "draft" | "release" };
  reason:  { provider: "deepseek"; model: string };
  asr:     { provider: string; model: string; revision?: string };
  tts:     { provider: string; model: string; voiceId?: string };
  boundAt: string;          // 切换生效的时刻
  source:  "ui" | "config" | "rollback";
};

// 每个资产自带出生证明，不可变
type ClipAsset = { /* …V2.1 原有字段… */ modelBinding: ModelBinding; createdAt: string };
type CompilationAsset = { /* … */ modelBinding: ModelBinding; clipIds: string[] };
```

关键：`ModelBinding` 是**快照**，不是引用。切换后再查这个资产，拿到的永远是它生成时的那个绑定。

---

## 4. 门禁矩阵

| 场景 | 允许切到 | 禁止 | 界面表现 |
|---|---|---|---|
| 开发/草稿（无发布意图） | 任意 | — | 正常下拉 |
| 作品已进入 release 流程 | 只能切 **H3 768P / H3 2K** | Lite | Lite 项置灰，悬浮提示"正式作品需 H3 产出" |
| 该 compilation 已有 ≥1 个合格片段 | 只能切到**同 profile 内的分辨率** | 换 provider / 换 model | 提示"如需换模型，请新建成片工程" |
| C6 评测运行中 | 全部锁定 | 任何切换 | 顶部黄条"评测进行中，模型已锁定" |
| 已发布 release | 全部锁定 | 任何切换 | 只读展示"本片由 MiniMax-H3 2K 生成" |

**最后一行是重点**：已发布的资产不能"换个模型重新登记"，那不是切换，那是篡改。

---

## 5. UI 规格

放在制作台的"生成设置"里，一个下拉 + 三行说明：

```
视频模型   [ MiniMax-H3 · 2K ▾ ]
           ├ MiniMax-H3 · 2K      0.80 元/秒   ← 当前
           ├ MiniMax-H3 · 768P    0.50 元/秒
           └ MiniMax-H3-Lite·480P 0.16 元/秒   （草稿专用，不可发布）

本次预计：150 秒 × 0.80 = 120 元        余额：xxx 元
```

三条必须常驻的提示：

1. **成本预览**：秒数 × 单价，切换时实时变。不做这个，等于让人闭着眼花钱。
2. **效果说明**：切 Lite 时显示"仅用于调试，画质不等同正式作品，且不可发布"。
3. **来源徽标**：成片封面角落常驻 `H3 · 2K` 或 `Lite · 480P`，导出时写进文件名。

---

## 6. 切换时正在运行的任务怎么办

| 状态 | 处理 |
|---|---|
| 已提交、正在生成 | **不打断、不改写**，按提交时的绑定跑完；界面标"旧模型任务进行中" |
| 排队中、未提交 | 按新绑定提交 |
| 已完成、待审 | 不动；审核通过后进入其所属 compilation |
| 失败、待重试 | 重试**沿用原绑定**；要换模型必须显式"新建任务" |

**一句话**：切换只影响"还没提交的"，不追认"已经提交的"。

---

## 7. 和"切换分辨率"的区别（别混）

| | 切换分辨率 | 切换模型 |
|---|---|---|
| 本质 | 同一作品的不同呈现 | 不同来源的不同作品 |
| 时间轴 | 必须完全一致 | 可以完全不同 |
| 索引 | 三档共用一套 | 各建各的 |
| 成本 | 0 元（本地转码） | 差 5 倍 |
| 可逆 | 随时切回 | 不可逆（已花的钱收不回） |
| 官方意义 | 体验功能 | **决定作品是否"由正式模型产出"** |

所以：分辨率可以随便切，模型切换必须留痕。

## 8. 最小实现（约半天）

| 步骤 | 工作量 | 说明 |
|---|---|---|
| 1. 配置表加 `profiles` 白名单 | 1 小时 | V2.1 §29.1 已有雏形，补 `publishable` 与单价 |
| 2. `ModelBinding` 落到 `ClipAsset` / `CompilationAsset` | 1.5 小时 | 现有字段已有 provider/model/profile，补 `boundAt` 与快照化 |
| 3. 一个 `ModelPicker` 组件 + 成本预览 | 2 小时 | 纯前端 + 一个 GET 配置接口 |
| 4. 门禁校验（后端） | 1 小时 | 发布前校验 `profile === release && model === H3` |
| 5. 徽标与导出文件名 | 0.5 小时 | `…_H3-2K.mp4` |

**不需要**重写 provider 抽象——V2.1 §5 本来就要加 MiniMax 适配器，切换面板只是它的一个消费者。

## 9. 验收用例

| 用例 | 操作 | 通过条件 |
|---|---|---|
| M1 向前生效 | 用 Lite 生成 1 镜头 → 切 H3 → 再生成 1 镜头 | 两个资产的 `modelBinding` 不同且各自正确 |
| M2 不可混拼 | 尝试把 Lite 与 H3 片段放进同一 compilation | 被拒，提示新建工程 |
| M3 发布门禁 | compilation 用 Lite → 点导出 | 导出禁用，说明理由 |
| M4 评测锁定 | C6 运行中尝试切换 | 被拒，黄条常驻 |
| M5 成本预览 | 150 秒下在 2K/768P 间切换 | 显示 120 元 / 75 元 |
| M6 已发布不可改 | 对已发布 release 发起切换 | 只读，无操作入口 |

---

## 10. 风险

| 风险 | 缓解 |
|---|---|
| 用户以为切了模型，旧片画质会变好 | 切换后旧片角落仍显示 `Lite · 480P`，并提示"画质不会追溯改变" |
| 混用导致索引串档 | compilation 与索引同时绑定 `modelBinding`，不匹配直接拒绝 |
| 切换忘记留痕 | `boundAt` + `source` 字段，日志里能回答"谁在什么时候换的" |
| 成本失控 | 切换即显示预计金额，超过本轮检查卡上限直接禁用提交 |
