# 分辨率与多档播放设计

> 需求来源：分辨率暂不定死，希望"使用时可以自由切换"。
> 结论先说：**生成一次、导出一个母版、播放端给三档。** 三档由本地转码产生，**0 元模型成本**、不影响索引、不影响交付。

---

## 1. 先把三个"分辨率"分开

这三个东西在讨论里最容易糊在一起，一糊就会得出错误结论（比如"切到 480P 就等于用了 Lite"）。

| 层 | 是什么 | 谁决定 | 能不能运行时切换 |
|---|---|---|---|
| **生成分辨率** | 调 MiniMax 时的 `480P / 768P / 2K` | profile 配置（`draft` / `release`） | ❌ 不能。已生成的片就是那个画质，切换配置不改变旧资产 |
| **交付分辨率** | 提交给评委的 mp4 尺寸 | 一次决策，写进 `publication` 门禁 | ❌ 不能。提交包只有一份 |
| **播放分辨率** | 网页里 `<video>` 拉哪一档 | 用户手动选 / 自动降档 | ✅ **能，这就是你要的功能** |

所以"自由切换分辨率"的正确实现是**第三条**：母版固定 1080p，播放端提供 1080/720/480 三档，用户随时切。

---

## 2. 母版与转码梯度

### 2.1 母版（唯一真源）

```
release 生成 2K 原始片段
  → 本地整合（旁白、字幕、转场）
  → 导出 deliver_1080p.mp4   ← 交付物，进提交包
```

```bash
ffmpeg -i master_prores.mov \
  -vf "scale=1920:1080:flags=lanczos,fps=25,setsar=1" \
  -c:v libx264 -profile:v high -level 4.1 -crf 18 -pix_fmt yuv420p \
  -c:a aac -b:a 192k -ar 48000 -ac 2 \
  -movflags +faststart \
  deliver_1080p.mp4
```

### 2.2 播放档位（应用内，不进提交包）

```bash
# 720p
ffmpeg -i deliver_1080p.mp4 -vf "scale=1280:720:flags=lanczos,fps=25,setsar=1" \
  -c:v libx264 -crf 20 -pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart play_720p.mp4

# 480p（省流档，标注"仅调试/弱网"）
ffmpeg -i deliver_1080p.mp4 -vf "scale=854:480:flags=lanczos,fps=25,setsar=1" \
  -c:v libx264 -crf 22 -pix_fmt yuv420p -c:a aac -b:a 96k -movflags +faststart play_480p.mp4
```

**统一从母版转码，不要从 720p 再转 480p**（二次损失）。

体积参考：150 秒 1080p 约 25—40 MB，720p 约 12—18 MB，480p 约 6—9 MB。两册共约 100 MB，可接受。

## 3. 一条硬约束：三档必须共用同一条时间轴

这是整个功能唯一的真正风险点。

索引（对象轨迹、场景文字、事件时间）绑定的是**时间轴**，不是文件。只要三档满足下面四条，索引对三档同时有效：

| 约束 | 要求 | 校验方法 |
|---|---|---|
| 帧率相同 | 全部 25 fps | `ffprobe -show_entries stream=r_frame_rate` |
| 总时长相同 | 差值 ≤ 40 ms | `format=duration` 三档对比 |
| 总帧数相同 | `nb_frames` 三档相等 | `-count_frames` |
| 起点一致 | 同一次整合导出，不做独立 `-ss` 裁切 | 抽查首帧画面 |

**不满足就必须拒绝加载该档**，宁可让用户看到错误，也不要给出错位的框。

> 为什么坐标不受影响：项目用的是归一化坐标 `(u,v) ∈ [0,1]²`（V2.1 §15.4），与像素尺寸无关；`object-fit: contain` 的内容区按容器实时计算，也不依赖 `videoWidth`。**唯一依赖尺寸的是"文字框是否看得清"，而那是画质问题，不是坐标问题。**

## 4. 前端实现

### 4.1 数据结构

```ts
type Rendition = {
  height: 1080 | 720 | 480;
  src: string;
  bytes: number;
  duration: number;   // 秒，与母版差 ≤0.04
  fps: number;        // 25
  nbFrames: number;
  sha256: string;
};

type MediaRelease = {
  releaseId: string;
  timelineVersion: string;   // 索引绑这个，不绑档位
  renditions: Rendition[];
  defaultHeight: 720;
};
```

**关键**：`timelineVersion` 与档位无关；`sha256` 只用于完整性校验，不参与"版本一致"判断。否则每切一次档位就会被判成"媒体版本变了"，把会话历史全冲掉。

### 4.2 切换逻辑（保留进度）

```ts
async function switchRendition(next: 1080 | 720 | 480) {
  const t = video.currentTime;
  const wasPlaying = !video.paused && !video.ended;
  const turnBefore = currentTurnId;          // 记录，切换不得作废当前轮次

  const r = release.renditions.find(x => x.height === next)!;
  await assertTimelineCompatible(r);          // 时长/帧率不符直接抛错

  video.src = r.src;
  video.load();
  await once(video, "loadedmetadata");
  video.currentTime = Math.floor(t * 25) / 25; // 对齐到帧，避免落在两帧之间
  if (wasPlaying) await video.play();

  if (currentTurnId === turnBefore) { /* 同一轮，状态不动 */ }
}
```

### 4.3 交互规则

| 场景 | 行为 |
|---|---|
| 播放中切换 | 保留 `currentTime` 与播放状态，切换后继续；误差 ≤ 0.1 s |
| 暂停中切换 | 保留帧位置，仍暂停；已画的对象框保留（坐标不变） |
| 回答播报中切换 | **允许**，音频是独立通道，不受影响；不取消当前轮次 |
| 切换失败 | 回退到切换前的档位，提示"这一档加载失败"，不静默降级 |
| 自动模式 | 默认 720p；连续卡顿 2 次或 `downlink < 1.5 Mbps` 时降 480p，不自动升 |

### 4.4 入口与文案

放在阅读设置面板里，三个单选项 + 一个"自动"：

- 高清 1080P（默认用于投屏/评委观看）
- 流畅 720P（默认）
- 省流 480P —— 副标题写"仅调试或弱网，正式演示请用高清"

**不要**用"标清/超清"这类营销词，评委分不清。直接写像素。

## 5. 与官方交付的关系（必须写清，避免自己骗自己）

| 事项 | 规则 |
|---|---|
| 提交包里的 4 个 mp4 | **只放 1080P 母版导出的那一个文件**，多档不进包 |
| 交互演示视频录制 | **必须切到 1080P 档再录**，否则等于自证画质不达标 |
| 说明书 | 写明"应用内提供 1080/720/480 三档，交付母版为 1080P" |
| 480P 档 | 界面标注"仅调试"；不得出现在任何提交录屏里 |

> 一句话：**多档是体验功能，不是画质豁免。** 母版不达标，切到 4K 也没用。

## 6. 验收用例（并入 C7 / T24）

| 用例 | 操作 | 通过条件 |
|---|---|---|
| R1 切换保进度 | 播放到 37.4 s 切 480p | 切换后时间在 37.3—37.5 s，继续播放 |
| R2 暂停保框 | 暂停并框出对象后切换 | 框位置不变，仍指向同一对象 |
| R3 回答中切换 | TTS 播报中点切换 | 播报不中断，问答不重来 |
| R4 时间轴一致 | 抽查三档 `nb_frames` | 三档完全相等 |
| R5 版本不变 | 切换后再提问 | 会话历史连续，不出现"版本冲突" |
| R6 拒坏档 | 人为放一个时长差 1 s 的文件 | 明确报错，不出错位框 |

## 8. 如果以后想改交付分辨率

只改三处，其余不动：

1. §29.1 `publication.min_width/min_height`（例如 1920×1080）
2. 母版导出命令里的 `scale`
3. 转码梯度的最高档

索引、坐标、交互逻辑**全都不用改**——因为它们是归一化的、绑时间轴的。这也是为什么第 3 节的四条一致性约束值得一开始就守住。
